# ItiOptimiser

VRChat向けアバターのダウンロードサイズおよびテクスチャ容量を削減するためのUnityエディタ拡張機能です。

複数の衣装を着せ替えたアバターでは、衣装ごとに用意されたテクスチャが必要以上の解像度や形式のまま残り、全体の容量が肥大化しがちです。
ItiOptimiserは、**外見を損なわずに削減可能な箇所**を自動で検出し、確認の上で一括修正します。

## 機能の概要

| 機能 | メニュー | 変更対象 | 復元の可否 |
|---|---|---|---|
| 解析 | `Tools > ItiOptimiser > 解析` | 変更なし | — |
| アセット最適化 | `Tools > ItiOptimiser > 開く` | プロジェクト内アセットのインポート設定（`.meta`） | 変更履歴から復元可能 |
| テクスチャアトラス化 | `Tools > ItiOptimiser > 選択中のアバターにテクスチャアトラス化を追加` | ビルド時の複製オブジェクトのみ（シーン上のアバターおよび元アセットは非破壊） | コンポーネントの削除で復元可能 |

| 項目 | 要件 |
|---|---|
| Unity | 2022.3 |
| VRChat SDK - Avatars | 3.10.0 以上、4.0.0 未満 |
| NDMF | 1.14.3 以上、2.0.0 未満 |

## 導入方法

### VCC（推奨）

1. **[VCCに追加](https://lil2943.github.io/ItiOpti/vcc.html)** をクリックします。VCCが起動し、リポジトリの追加画面が表示されます（ブラウザに確認が表示された場合は「開く」を選択してください）。
2. VCCで対象のプロジェクトを開き、パッケージ一覧からItiOptimiserを追加します。

[配布ページ](https://lil2943.github.io/ItiOpti/)からも同じように追加できます。

「VCCに追加」が反応しない場合は、VCCの設定画面から以下のURLをリポジトリとして手動で登録してください。

```
https://lil2943.github.io/ItiOpti/index.json
```

### GitHub Releases

[Releases](https://github.com/lil2943/ItiOpti/releases)から以下のいずれかを入手してください。

| ファイル | 用途 |
|---|---|
| `dev.hisokakaori.hkopti-<バージョン>.zip` | VPMパッケージ形式 |
| `dev.hisokakaori.hkopti-<バージョン>.unitypackage` | Unityへの直接インポート形式（VRChat SDKおよびNDMFの事前導入が必要） |

※`.zip`と`.unitypackage`は同一バージョンのソースコードから自動生成されているため、パッケージの内容は同等です。

## 使い方 1：解析

`Tools > ItiOptimiser > 解析`

アバターの負荷状況を診断して表示します。**既存のデータが変更されることはありません。**

### 操作手順

1. 「対象アバター」にアバターのルートオブジェクト（VRC Avatar Descriptorが配置されたオブジェクト）を指定します。ヒエラルキー上で選択し、「選択中を使う」を押すことでも指定可能です。
2. Quest向けの基準で判定したい場合は、「Quest / Android の基準で判定する」にチェックを入れます。
3. 「解析する」をクリックします。

### 表示項目

| 項目 | 内容 |
|---|---|
| 総合ランク | VRChatのPerformance Rank。判定基準は導入されているVRChat SDKの設定値に準拠します。 |
| 足を引っ張っている項目 | パフォーマンスランクの低下要因となっている項目です。 |
| 項目ごとの表 | 現在の数値・判定・上位ランクへ到達するための上限値を示します。 |
| テクスチャの内訳 / マテリアルの内訳 / ボーンの内訳 | アコーディオン形式（折りたたみ）で内訳を表示します。 |
| 警告（自動では触りません） | 注意を要する箇所です。ItiOptimiserが自動で変更を加えることはありません。 |
| 保護レベルの集計 | 絶対保護 / 規約保護 / 参照あり / 参照なし の該当件数を集計して表示します。 |
| 他ツールとの併用に関する警告 | 後述の「[他のツールとの併用](#他のツールとの併用)」に関する注意事項を表示します。 |

> **本画面にはビルド前の状態が表示されます。** Modular AvatarやVRCFuryなどにより、ビルド時に追加・変更される要素は反映されません。

## 使い方 2：アセット最適化

`Tools > ItiOptimiser > 開く`

テクスチャやモデルの**インポート設定**を包括的に見直します。画面は「設定・実行」タブと「変更履歴」タブで構成されています。

### 基本手順

1. 「設定・実行」タブで解析対象を選択します。
2. 「調べる」をクリックします（この段階では変更は適用されません）。
3. 検出された候補一覧を確認し、適用したい項目にチェックを入れます。
4. 「バックアップして適用する」をクリックします。

### 対象の選択方法

| 対象 | 内容 |
|---|---|
| Selected Avatar（既定） | 指定した1体のアバターが参照しているアセットのみを調査します。 |
| All In Scene | 現在開いているシーン内の全アバターが参照しているアセットを網羅的に調査します。 |

**解像度の削減を行う場合は「All In Scene」の利用を推奨します。** 同一のテクスチャが別のアバターにおいてより大きな表示領域で使用されている場合、双方を同時に検証しないと、他方のアバターでテクスチャが粗く描画される恐れがあるためです。

### 最適化の種類

| 種類 | 検出条件 | 変更内容 | 「安全項目を選択」時の挙動 |
|---|---|---|---|
| アルファ不要 | フォーマットがアルファ付き（DXT5・BC7・RGBA32等）であるにもかかわらず、元画像にアルファチャンネルが存在しない場合（法線マップは除外）。 | アルファの読み込みを無効化し、フォーマットをPC向けはDXT1、Android向けはETC2_RGB4へと変更します。 | 自動選択される |
| 単色 | 画像内の全ピクセルが同一の色で構成されている場合。 | 最大解像度を32pxに縮小します。 | 自動選択される |
| 解像度が過大 | テクセル密度（後述）の観点から、要求される解像度を過剰に上回っている場合。 | 最大解像度を推奨値まで引き下げます。 | **選択されない** |
| Texture Read/Write | テクスチャのRead/Write機能が有効になっている場合。 | 無効化します。 | **選択されない** |
| Read/Write | モデル（FBX等）のRead/Write機能が有効になっている場合。 | 無効化します。 | **選択されない** |
| Crunch 圧縮 | 後述の「Crunch 圧縮」の項目を参照してください。 | Crunch圧縮を有効化します。 | **選択されない** |

※「選択されない」項目は、外観の質感や他ツールの動作に影響を及ぼす可能性があるため、変更内容を確認した上で個別にチェックを入れてください。

※`Packages`ディレクトリ配下のアセットは読み取り専用属性となるため、候補として検出された場合でも設定の変更は行えません。

### 解像度の削減

アバターの表面積に対してテクスチャが実際に表示される比率（テクセル密度）を算出し、過剰な解像度を持つテクスチャの最大サイズを引き下げます。

「積極度」の選択により基準値を切り替えることができます。

| 積極度 | 算出基準 | 特徴 |
|---|---|---|
| Safe | 1mあたり2048pxを基準とし、さらに1段階（2倍）の安全マージンを確保 | 最も安全側に倒した設定です。容量の削減幅は控えめとなります。 |
| Standard | 1mあたり2048pxを基準とする | 計算上の適正値へと設定を調整します。 |
| **Aggressive（既定）** | 1mあたり1536pxを基準とする | 最も大きな削減効果を発揮します。 |

内部計算における適用ルールは以下の通りです。

- マテリアル名またはテクスチャ名に `face` `eye` `mouth` `head` `hair` `顔` `目` `髪` が含まれる場合、至近距離での視認性が重視される部位とみなし、基準密度を2倍として計算します。
- 法線マップやマスク画像（プロパティ名に `Bump` `Normal` `Mask` を含むもの）は、基準密度を0.5倍として計算します。
- 推奨解像度は2の累乗値へと切り上げ処理を行い、64px〜8192pxの範囲に収めます。
- 512px未満のテクスチャは処理対象から除外されます。
- 1枚のテクスチャが複数のマテリアルから共有されている場合は、最も要求解像度の高い条件に合わせます。
- 複数のアバターを一括検証した場合も、最も高い要求解像度を優先して適用します。
- 検証したアバターのうち1体でも必要な解像度を算出できなかったテクスチャは、安全のため最適化候補から除外します。
- 算出された推奨解像度が現在の設定解像度を下回る場合に限り、最適化候補として提示されます。

解像度の低下によってテクスチャの粗さが目立つ場合は、変更履歴から設定をロールバックし、積極度の設定を緩和した上で再実行してください。

### Crunch 圧縮

「Crunch 圧縮も候補に出す」にチェックを入れることで、最適化の候補欄に追加されます（初期設定はオフ）。

| 項目 | 内容 |
|---|---|
| 効果 | **ダウンロードサイズのみ**が削減されます。実行時に消費されるメモリ（VRAM）のフットプリントは変動しません。 |
| 対象 | 現在のフォーマットがDXT1またはDXT5であり、サイズが256px以上、かつ法線マップを除いた未Crunch圧縮のテクスチャ。 |
| 品質 | 75（設定範囲0〜100。Unity標準のデフォルト値は50）。 |
| 削減見込み | 候補一覧には予測値を表示しません。実質的な削減効果はアップロード後に確認する必要があります。 |

留意事項：

- 非可逆圧縮に伴い画質がわずかに劣化します。適用後は必ずアバターの外観を確認してください。
- インポート処理に長時間を要します。対象のファイル数によっては完了まで数十分程度かかる場合があります。
- **Android（Quest）向けのビルド環境においてはサイズ削減効果が得られません。**
- 法線マップへ適用した場合、陰影計算にノイズが生じやすいため、自動的に対象外としています。

### バックアップおよび復元手順

「バックアップして適用する」を実行すると、変更が加えられる前に対象アセットの`.meta`ファイルが以下のディレクトリ構造へと退避されます。

```
<Unity プロジェクトのフォルダ>/ItiOptimiser_Backup/AssetImportSettings/<日時>/
```

当該ディレクトリ内には`.meta`ファイルの複製に加え、変更の記録ログ（`manifest.json`および予備用の`manifest.backup.json`）が保存されます。
この記録には、処理対象となったアバターの識別名、シーン名、および階層パス情報が保持されています。

変更前の状態へ復元する場合は「変更履歴」タブを使用します。

1. 「アバター」の入力欄に対象アバターを指定します（「選択中」ボタンによる指定も可能です）。
2. 指定したアバターに対して過去に実行された変更ログの一覧が表示されます。
3. 復元したい履歴の行にある「元に戻す」をクリックします。

| ボタン・項目 | 動作内容 |
|---|---|
| 元に戻す | バックアップ時点の`.meta`ファイルを書き戻し、Unity側で再インポート処理を走らせます。 |
| フォルダを開く | 当該のバックアップが格納されているフォルダをエクスプローラーで開きます。 |
| 削除 | 選択したバックアップ履歴を削除します。**適用済みの設定自体は維持されますが、該当する履歴を用いたロールバックは行えなくなります。** |
| すべてのアバターの履歴を表示 | 指定したアバターに関係なく、プロジェクト全体のバックアップ履歴を網羅して一覧表示します。 |
| 履歴を更新 | 保存されている履歴データを再読み込みし、一覧を最新の状態へ更新します。 |

プレハブからアバターを再配置した場合など、記録時と同一のアバターインスタンスとして追跡できないケースがあります。
そのような状況では、アバター名とヒエラルキーの階層パスの一致情報に基づき「（推定）」というラベルを付与して履歴を表示します。候補が見当たらない場合は、「すべてのアバターの履歴を表示」機能をご活用ください。

なお、安全管理のため、設定の書き戻し先は現在のUnityプロジェクトの`Assets`フォルダ配下に限定されています。

## 使い方 3：テクスチャアトラス化

複数枚のテクスチャに含まれる**未使用領域（余白）**を再パッキング（統合）し、テクスチャ全体のメモリ占有量を削減します。

### 操作手順

1. ヒエラルキー上でアバターを選択します（衣装や髪などの子オブジェクトを選択している場合でも、親階層を自動探索してアバターのルートを特定します）。
2. `Tools > ItiOptimiser > 選択中のアバターにテクスチャアトラス化を追加` を実行します。
3. そのまま通常通りアバターのアップロード（ビルド）を行います。

アバターのルートオブジェクトに対し、インスペクターから直接 `ItiOptimiser > Texture Atlas` コンポーネントをアタッチすることでも同等の動作となります。

本処理はビルド実行時（NDMFのOptimizingフェーズ内）において、生成された複製アバターに対して非破壊的に適用されます。**シーン上に存在するアバター本体および元のアセットデータが書き換えられることはありません。**
実行結果は、ビルド時にUnityのConsoleウィンドウへ出力されます。

### 設定項目一覧

| 項目 | 既定値 | 内容 |
|---|---|---|
| Enabled | 有効（オン） | チェックを外すと、アトラス化の処理をスキップします。 |
| Level | 保守的（Conservative） | 最適化の適用レベルを指定します。詳細は下表を参照してください。 |
| Max Atlas Size | 4096 | 生成されるアトラス化テクスチャの最大解像度です（256〜8192の範囲に収めて扱われます）。 |
| Padding Pixels | 8 | テクスチャ領域間に設けるパディング余白です（0〜32）。境界線において隣接色の滲み出しが発生する場合は数値を引き上げてください。 |
| Exclude | 指定なし | アトラス化の対象から除外したいマテリアルを登録します。 |
| Exclude Renderers | 指定なし | アトラス化の対象から除外したいRendererコンポーネントを登録します。 |

※1体のアバターに対してTexture Atlasコンポーネントが複数重複してアタッチされている場合、最初に検出された1つのみが処理に用いられます。

### 適用レベル（Level）の分類

| 段階 | 挙動の詳細 |
|---|---|
| **保守的（既定）** | 視覚的な破綻を招くリスクのある要素を回避します。タイリング処理（UV座標が0〜1の基準範囲外を指している状態）を前提とするマテリアルは除外されます。 |
| 設定の違いを吸収 | Cutoutの閾値設定やアウトラインの線幅パラメータが異なるマテリアル同士であっても、可能な限り統合してパッキングします。 |
| 最大限まとめる | タイリング処理を含むマテリアルも統合の対象に含めます。意図せぬ描画の乱れが生じた場合は、ユーザー側で個別に除外設定を行う前提のモードです。 |

※作者の開発検証環境においては、上位2段階の設定を適用した場合でも、保守的モードとの削減率の差は0〜2ポイント程度に留まりました。**原則として「保守的」のまま運用いただく形で十分な効果が得られます。**

### 自動除外が適用される条件

意図しない描画の乱れを防止するため、以下の条件に該当する場合は自動的にアトラス化の処理から除外されます。

- アトラス化を施すことにより、かえってテクスチャ容量の**増加**が見込まれる場合。
- マテリアルスロット数がサブメッシュ数を超過しているRenderer（同一フェースに対して異なるマテリアルを多重描画する構成）で使用されているマテリアル。
- 同一メッシュ内の同一部位に対し、Rendererごとに異なるマテリアルがバインドされている場合。
- メッシュデータ内にUV座標情報が定義されていない場合。
- 適用レベルが「保守的」または「設定の違いを吸収」において、UVタイリングを使用しているマテリアル。
- TexTransToolによるアトラス化処理と競合している場合（後述の併用項目を参照）。

統合対象の領域が指定の最大解像度に収まりきらない場合は、パッキング領域を自動で縮小しながら再試行が行われます。

### 処理に伴い生成される要素

- 再パッキングされたテクスチャデータ（アルファが必要なものはDXT5、不要なものはDXT1形式にて圧縮されます）。
- UV座標の再マッピングが行われたメッシュデータ（ポリゴン三角形数とBlendShapeの構成は維持されます。1つの頂点を異なる配置先の領域で共有している場合は、その頂点が複製されるため、頂点数がわずかに増えることがあります）。
- 同一マテリアルへと統合されたサブメッシュは1つに結合され、結果としてマテリアルスロット数が削減される場合があります。

描画に破綻が生じたマテリアルについては、「Exclude」の指定リストへ登録して除外してください。

## 他のツールとの併用

ツールの併用可否は機能ごとに独立して判定されます。

| 連携対象ツール | アセット最適化 | テクスチャアトラス化 |
|---|---|---|
| Modular Avatar | 併用可能 | 併用可能 |
| Avatar Optimizer | 併用可能 | 併用可能 |
| TexTransTool | 併用可能 | **機能が重複するためItiOptimiser側の処理を自動抑止**（ビルド処理は中断せず、Consoleへ警告を出力） |
| VRCFury | 併用可能 | 併用可能（ビルド時に階層の移動やリネームが実行されるため、出力結果の外観確認を推奨） |
| VRC Quest Tools | 併用可能 | 併用可能（ビルドプロセス内でマテリアルとテクスチャの再生成が行われるため、Quest環境下での描画確認を推奨） |

※アセット最適化に含まれる「Read/Write」および「Texture Read/Write」の項目は、ビルド時にメッシュ構造やテクスチャのピクセル情報を動的に読み取るツールと併用した場合、相手側の処理がエラーとなる可能性があります。そのため、これらの設定項目は自動一括選択の対象外となっています。

## 作者の環境での実測結果

以下は検証環境における参考値です。**実際の削減効果は、対象となるアバターの構造やアセットの構成内容によって変動します。**

### アセット最適化

| 検証アバター | 適用設定 | 実測結果 |
|---|---|---|
| Chocolat（多数の衣装を同梱） | 解像度の削減：Aggressive | ダウンロードサイズが**約120MBから35.71MBへ削減**。目視による外観の著しい劣化は認められませんでした。 |

### テクスチャアトラス化（保守的モード）

ビルド完了後におけるテクスチャ容量の比較データです（ダウンロード時のファイルサイズとは異なります）。

| 検証アバター | 実測結果 |
|---|---|
| Chocolat | 90.6MB → 75.0MB（約17%削減） |
| Zome | 224.9MB → 210.4MB（約6%削減） |

いずれの検証ケースにおいても、アトラス化の前後で頂点数、ポリゴン三角形数、BlendShape数、およびRendererコンポーネント数に増減は生じていません。
また、保守的モードを通して出力されたアバターを目視確認した範囲において、テクスチャ品質の明らかな破綻がないことを確認済みです。

## 制限事項・注意点

- **最適化の適用後は、必ずご自身の目視により外観の確認を行ってください。** 内部的な計算数値に異常がない場合でも、描画クオリティの最終的な許容判断は人間の視覚による確認が不可欠です。
- アセット最適化機能は、プロジェクト内に保存されているアセットのインポート設定を直接上書きします。変更前のデータは自動でバックアップされますが、重要なプロジェクトにおいては、事前にプロジェクト全体の退避やバージョン管理システム（Git等）によるコミットを行うことを強く推奨します。
- 解像度の削減処理は、検証対象として指定されたアバターのパラメータのみを基準に算出されます。別シーンのアバターが同一のテクスチャを共有している場合、そちら側で解像度不足によるボケ等が生じるリスクがあります。
- Crunch圧縮設定は、Android（Quest）向けビルドに対してはファイルサイズの削減効果を持ちません。
- 解析画面に表示される各種メトリクスは、ビルド処理が走る前の静的な状態に基づいています。
- パッケージ識別用IDおよび名前空間（Namespace）には、過去バージョンとの後方互換性を維持する目的から旧名称（`dev.hisokakaori.hkopti` / `HisokaKaori.HKOpti`）が一部残存しています。
