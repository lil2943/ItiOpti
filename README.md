# ItiOptimiser

VRChat アバターのダウンロードサイズとテクスチャ容量を減らすための Unity エディタ拡張です。

複数の衣装を着せたアバターでは、衣装ごとに用意されたテクスチャが必要以上の解像度や形式のまま残り、容量が膨らみがちです。
ItiOptimiser は、**見た目を変えずに削れる箇所**を検出し、確認したうえでまとめて修正します。

## 機能の概要

| 機能 | メニュー | 何を変更するか | 元に戻せるか |
|---|---|---|---|
| 解析 | `Tools > ItiOptimiser > 解析` | 何も変更しない | — |
| アセット最適化 | `Tools > ItiOptimiser > 開く` | プロジェクト内アセットのインポート設定（`.meta`） | 変更履歴から戻せる |
| テクスチャアトラス化 | `Tools > ItiOptimiser > 選択中のアバターにテクスチャアトラス化を追加` | ビルド時の複製だけ。シーン上のアバターと元アセットは変更しない | コンポーネントを外せば元通り |

## 動作環境

| 項目 | 要件 |
|---|---|
| Unity | 2022.3 |
| VRChat SDK - Avatars | 3.10.0 以上、4.0.0 未満 |
| NDMF | 1.14.3 以上、2.0.0 未満 |

VCC から導入した場合、VRChat SDK と NDMF は依存関係として自動で解決されます。

## 導入方法

### VCC（推奨）

1. [配布ページ](https://lil2943.github.io/ItiOpti/) を開き、「VCCに追加」を押します
2. VCC でプロジェクトを開き、パッケージ一覧から ItiOptimiser を追加します

「VCCに追加」が反応しない場合は、VCC の設定画面で次の URL をリポジトリとして手動で追加してください。

```
https://lil2943.github.io/ItiOpti/index.json
```

### GitHub Releases

[Releases](https://github.com/lil2943/ItiOpti/releases) から次のいずれかを入手できます。

| ファイル | 用途 |
|---|---|
| `dev.hisokakaori.hkopti-<バージョン>.zip` | VPM パッケージ |
| `dev.hisokakaori.hkopti-<バージョン>.unitypackage` | Unity にインポートする形式。VRChat SDK と NDMF は別途導入が必要 |

`.zip` と `.unitypackage` は同じバージョンのソースから自動生成されるため、中身は同一です。

## 使い方 1：解析

`Tools > ItiOptimiser > 解析`

アバターの負荷を調べて表示します。**データは一切変更しません。**

### 操作

1. 「対象アバター」にアバターのルート（VRC Avatar Descriptor が付いたオブジェクト）を指定します。ヒエラルキーで選択して「選択中を使う」を押しても指定できます
2. Quest 向けに判定したい場合は「Quest / Android の基準で判定する」にチェックを入れます
3. 「解析する」を押します

### 表示される内容

| 項目 | 内容 |
|---|---|
| 総合ランク | VRChat の Performance Rank。判定基準は導入されている VRChat SDK 内の設定値から読み込みます |
| 足を引っ張っている項目 | ランクを下げている原因の項目 |
| 項目ごとの表 | 現在の値・判定・次のランクの上限 |
| テクスチャの内訳 / マテリアルの内訳 / ボーンの内訳 | 折りたたみで表示 |
| 警告（自動では触りません） | 注意が必要な箇所。ItiOptimiser が自動で変更することはありません |
| 保護レベルの集計 | 絶対保護 / 規約保護 / 参照あり / 参照なし の件数 |
| 他ツールとの併用に関する警告 | 下記「[他のツールとの併用](#他のツールとの併用)」を参照 |

> **この画面はビルド前の状態を表示します。** Modular Avatar や VRCFury などがビルド時に追加・変更するものは含まれません。

## 使い方 2：アセット最適化

`Tools > ItiOptimiser > 開く`

テクスチャやモデルの**インポート設定**を見直します。画面は「設定・実行」タブと「変更履歴」タブに分かれています。

### 基本の流れ

1. 「設定・実行」タブで対象を選びます
2. 「調べる」を押します（この時点では何も変更しません）
3. 見つかった候補を確認し、適用したい項目にチェックを入れます
4. 「バックアップして適用する」を押します

### 対象の選び方

| 対象 | 内容 |
|---|---|
| Selected Avatar（既定） | 指定した 1 体が使っているアセットだけを調べます |
| All In Scene | 開いているシーン内の全アバターが使っているアセットを調べます |

**解像度の削減を使う場合は「All In Scene」を推奨します。** 同じテクスチャを別のアバターがより大きく使っている場合、そのアバターも一緒に調べないと、そちらで粗く見える可能性があるためです。

### 修正の種類

| 種類 | 検出する条件 | 変更内容 | 「安全項目を選択」で選ばれるか |
|---|---|---|---|
| アルファ不要 | 形式がアルファ付き（DXT5・BC7・RGBA32 など）なのに、元画像にアルファチャンネルが無い。法線マップは対象外 | アルファを読み込まない設定にし、PC は DXT1、Android は ETC2_RGB4 に変更 | 選ばれる |
| 単色 | 全画素がまったく同じ色 | 最大解像度を 32px に変更 | 選ばれる |
| 解像度が過大 | テクセル密度（後述）から見て、必要な解像度より大きい | 最大解像度を推奨値まで下げる | **選ばれない** |
| Texture Read/Write | テクスチャの Read/Write が有効 | 無効にする | **選ばれない** |
| Read/Write | モデル（FBX など）の Read/Write が有効 | 無効にする | **選ばれない** |
| Crunch 圧縮 | 下記「Crunch 圧縮」を参照 | Crunch 圧縮を有効にする | **選ばれない** |

「選ばれない」項目は、見た目や他ツールの動作に影響する可能性があるため、内容を確認したうえで個別にチェックを入れてください。

`Packages` 配下のアセットは読み取り専用のため、候補として表示されても変更できません。

### 解像度の削減

テクスチャが実際にアバター上でどれくらいの大きさで表示されるか（テクセル密度）を計算し、必要以上に大きいテクスチャの最大解像度を下げます。

「積極度」で基準を選べます。

| 積極度 | 基準 | 特徴 |
|---|---|---|
| Safe | 1m あたり 2048px、さらに 1 段階（2 倍）の余裕を残す | 最も安全。削減量は小さめ |
| Standard | 1m あたり 2048px | 計算どおりに下げる |
| **Aggressive（既定）** | 1m あたり 1536px | 最もよく減る |

計算上の規則は次のとおりです。

- マテリアル名またはテクスチャ名に `face` `eye` `mouth` `head` `hair` `顔` `目` `髪` が含まれる場合は、近くで見られる部位として基準を 2 倍にします
- 法線マップやマスク（プロパティ名に `Bump` `Normal` `Mask` を含むもの）は、基準を 0.5 倍にします
- 推奨値は 2 のべき乗に切り上げ、64px〜8192px の範囲に収めます
- 512px 未満のテクスチャは対象外です
- 1 枚のテクスチャを複数のマテリアルが使っている場合は、最も大きい要求に合わせます
- 複数のアバターを調べた場合も、最も大きい要求に合わせます
- 1 体でも計算できなかったテクスチャは、候補から外します
- 推奨値が現在の解像度より小さい場合だけ候補になります

粗く見えた場合は、変更履歴から元に戻し、積極度を下げてやり直してください。

### Crunch 圧縮

「Crunch 圧縮も候補に出す」にチェックを入れると、候補に追加されます（既定はオフ）。

| 項目 | 内容 |
|---|---|
| 効果 | **ダウンロードサイズだけ**が小さくなります。実行時のメモリ（VRAM）は変わりません |
| 対象 | 現在の形式が DXT1 または DXT5、かつ 256px 以上、かつ法線マップではなく、まだ Crunch 圧縮されていないテクスチャ |
| 品質 | 75（0〜100。Unity の既定は 50） |
| 削減見込み | 表示しません。効果はアップロードして確かめる必要があります |

注意点：

- 画質がわずかに低下します。適用後は必ず見た目を確認してください
- インポートに時間がかかります。枚数によっては数十分かかることがあります
- **Android（Quest）向けのビルドには効果がありません**
- 法線マップは陰影にノイズが出やすいため、対象外にしています

### バックアップと元に戻す方法

「バックアップして適用する」を押すと、変更前に対象アセットの `.meta` ファイルを次の場所へ保存します。

```
<Unity プロジェクトのフォルダ>/ItiOptimiser_Backup/AssetImportSettings/<日時>/
```

このフォルダには、`.meta` のコピーのほか、変更内容の記録（`manifest.json` と、その予備の `manifest.backup.json`）が保存されます。
記録には、調べた対象アバターの名前・シーン・階層パスも含まれます。

元に戻すには「変更履歴」タブを使います。

1. 「アバター」にアバターを指定します（「選択中」ボタンでも指定できます）
2. そのアバターに対して行った変更の一覧が表示されます
3. 戻したい行の「元に戻す」を押します

| ボタン・設定 | 内容 |
|---|---|
| 元に戻す | その時点の `.meta` に書き戻し、再インポートします |
| フォルダを開く | バックアップフォルダをエクスプローラーで開きます |
| 削除 | その履歴を削除します。**適用済みの設定は変わりませんが、その履歴からは元に戻せなくなります** |
| すべてのアバターの履歴を表示 | アバターを問わず、すべての履歴を表示します |
| 履歴を更新 | 一覧を読み込み直します |

アバターをプレハブから置き直した場合など、記録時と同じアバターだと識別できないことがあります。
その場合は、アバター名と階層パスが一致する履歴を「（推定）」と付けて表示します。見つからない場合は「すべてのアバターの履歴を表示」を使ってください。

復元時の書き戻し先は、現在の Unity プロジェクトの `Assets` フォルダ内に限定しています。

## 使い方 3：テクスチャアトラス化

複数のテクスチャに含まれる**使われていない余白**を詰め直し、テクスチャ容量を減らします。

### 操作

1. ヒエラルキーでアバターを選択します（衣装や髪などを選んでいても、親をたどってアバター本体を見つけます）
2. `Tools > ItiOptimiser > 選択中のアバターにテクスチャアトラス化を追加` を実行します
3. そのままアップロード（ビルド）します

アバターのルートに `ItiOptimiser > Texture Atlas` コンポーネントを手動で追加しても同じです。

処理はビルド時（NDMF の Optimizing フェーズ）に、アバターの複製に対して行われます。**シーン上のアバターと元のアセットは変更されません。**
処理結果はビルド時に Unity の Console へ出力されます。

### 設定項目

| 項目 | 既定値 | 内容 |
|---|---|---|
| Enabled | オン | オフにすると何もしません |
| Level | 保守的（Conservative） | 踏み込み具合。下表を参照 |
| Max Atlas Size | 4096 | アトラス 1 枚の最大サイズ。256〜8192 の範囲で扱われます |
| Padding Pixels | 8 | 詰め直した領域どうしの隙間（0〜32）。継ぎ目に別の色がにじむ場合は増やしてください |
| Exclude | なし | ここに入れたマテリアルはアトラス化しません |
| Exclude Renderers | なし | ここに入れた Renderer はアトラス化しません |

1 体のアバターに Texture Atlas が複数付いている場合は、最初の 1 つだけが使われます。

### 踏み込み具合（Level）

| 段階 | 内容 |
|---|---|
| **保守的（既定）** | 見た目が変わる要素には触りません。タイリング（UV が 0〜1 の範囲外）を使うマテリアルは対象外 |
| 設定の違いを吸収 | Cutout の閾値やアウトラインの太さが異なるマテリアルもまとめます |
| 最大限まとめる | タイリングを使うマテリアルも対象にします。崩れた場合は個別に除外する前提です |

作者の環境では、上の 2 段階を使っても削減量は保守的と比べて 0〜2 ポイントしか変わりませんでした。**通常は保守的のままで十分です。**

### 自動で対象外になるケース

見た目が崩れることを避けるため、次の場合はアトラス化を行いません。

- アトラス化するとかえってテクスチャ容量が**増える**と見積もられる場合
- マテリアルスロット数がサブメッシュ数より多い Renderer（同じ面を別のマテリアルで重ねて描く手法）で使われているマテリアル
- 同じメッシュの同じ部分に、Renderer ごとに異なるマテリアルが割り当てられている場合
- UV を持たないメッシュで使われているマテリアル
- 保守的・設定の違いを吸収 で、タイリングを使うマテリアル
- TexTransTool のアトラス化と重複する場合（下記参照）

最大サイズに入りきらない場合は、領域を縮小して再挑戦します。

### 生成されるもの

- 詰め直したテクスチャ（アルファが必要なものは DXT5、不要なものは DXT1 で圧縮）
- UV を書き換えたメッシュ（頂点数・三角形数・BlendShape は変わりません）
- 同じマテリアルになったサブメッシュは 1 つにまとめられ、マテリアルスロットが減る場合があります

見た目が崩れたマテリアルがある場合は、Exclude に追加してください。

## 他のツールとの併用

判定は機能ごとに行います。

| ツール | アセット最適化 | テクスチャアトラス化 |
|---|---|---|
| Modular Avatar | 併用可 | 併用可 |
| Avatar Optimizer | 併用可 | 併用可 |
| TexTransTool | 併用可 | **重複するため ItiOptimiser 側は実行しない**（ビルドは止めず、Console に警告を出す） |
| VRCFury | 併用可 | 併用可。ビルド時にオブジェクトが移動・改名されるため、結果を目視で確認してください |
| VRC Quest Tools | 併用可 | 併用可。ビルド時にマテリアルとテクスチャが作り直されるため、Quest 版の見た目を確認してください |

アセット最適化の「Read/Write」「Texture Read/Write」は、ビルド時にメッシュや画素データを読み取るツールと組み合わせると、そのツールが失敗する可能性があります。これらの項目は自動では選択されません。

## 作者の環境での実測結果

参考値です。**どれだけ減るかはアバターやアセットによって大きく異なります。**

### アセット最適化

| アバター | 設定 | 結果 |
|---|---|---|
| Chocolat（衣装多数） | 解像度の削減 Aggressive | ダウンロードサイズ **約 120MB → 35.71MB**。目視で劣化は確認されませんでした |

### テクスチャアトラス化（保守的）

ビルド後のテクスチャ容量の比較です（ダウンロードサイズではありません）。

| アバター | 結果 |
|---|---|
| Chocolat | 90.6MB → 75.0MB（17% 減） |
| Zome | 224.9MB → 210.4MB（6% 減） |

どちらもアトラス化の前後で頂点数・三角形数・BlendShape 数・Renderer 数は変化しませんでした。
また、保守的モードを通したアバターを実際に目視で確認し、見た目の劣化が無いことを確認しています。

## 制限事項・注意点

- **適用後は、必ずご自身の目で見た目を確認してください。** 数値上問題がなくても、見た目の判断は人にしかできません
- アセット最適化は、プロジェクト内のアセットのインポート設定を直接変更します。バックアップは自動で作成されますが、重要なプロジェクトでは、あらかじめプロジェクト全体のバックアップやバージョン管理を行うことをおすすめします
- 解像度の削減は、調べたアバターだけを基準に計算します。別のシーンのアバターが同じテクスチャを使っている場合、そちらで粗くなる可能性があります
- Crunch 圧縮は Android（Quest）向けビルドには効果がありません
- 解析画面はビルド前の状態を表示します
- パッケージ ID と名前空間には、互換性のため旧名称（`dev.hisokakaori.hkopti` / `HisokaKaori.HKOpti`）が残っています
